4. TEXTUREMAPWORKSPACE STATE ARCHITECTURE
============================================================

Added one shared authoring runtime instead of three separate runtimes.
The workspace tracks:

    - Sub-layer 0..3 state
    - COLORING / CONTOUR / PANEL_LINES mode
    - WORKING / COMMITTED preview source
    - EDIT / PREVIEW view mode
    - active/inactive texture channel catalog
    - selected default or named Surface Target
    - selected BOX_ATLAS face
    - RGBA paint state
    - emissive intensity
    - panel-line thickness and centralized color preset
    - contour points, closed state, and target action
    - logical-grid cursor and stroke state
    - editor zoom
    - working/original CPU images
    - dirty state and session revision

Temporary state remains workspace-owned. COMMIT is the explicit
working -> canonical in-memory boundary. SAVE is the explicit
canonical -> disk boundary.

Structural Q navigation is rejected while the working pass is dirty.
Returning to the branch setup or authoring-cycle setup discards the
uncommitted pass without changing the canonical target.

5. SHARED PIXEL-GRID IMPLEMENTATION
============================================================

All authoring modes share one logical-grid and editor-plane system:

    - inherited Layer 2 grid sizes: 32, 64, or 128
    - screen-facing XY edit canvas
    - FACE_0..FACE_5 selection
    - logical cell cursor/highlight
    - mouse-to-canvas and canvas-to-cell mapping
    - mouse-wheel editor zoom
    - Bresenham-style cell interpolation for continuous strokes
    - named Surface Target clipping
    - TAB EDIT/PREVIEW switching without recreating the session

Actual existing BOX_ATLAS_6_DIRECTION mapping was inspected and
centralized as:

    FACE_0 = +X
    FACE_1 = -X
    FACE_2 = +Y
    FACE_3 = -Y
    FACE_4 = +Z
    FACE_5 = -Z

The atlas is addressed as three columns by two rows.

New and actively rewritten implementation loops use postfix increment
where an increment expression is used, per the sprint format request.

7. BASE_COLOR / EMISSIVE_COLOR IMPLEMENTATION
============================================================

BASE_COLOR:
    - working copy or selected compatible source image
    - shared grid painting and commit to canonical texture data
    - panel lines also commit through the canonical Base Color channel

EMISSIVE_COLOR:
    - blank transparent image is created at canonical texture
      resolution when no emissive texture exists
    - RGBA painting uses the shared editor
    - intensity range 0.00..4.00, step 0.25, default 1.00
    - minimum renderer contribution added for self-lit preview
    - no global illumination, ray tracing, light sampling, or shadow
      behavior was introduced

============================================================
8. CONTOUR IMPLEMENTATION
============================================================

Implemented NEW and EDIT EXISTING workflows:

    - NEW locks its target to NEW
    - EDIT EXISTING cycles named committed targets only
    - implicit default Surface Target is not editable
    - no-target EDIT state locks authoring with a diagnostic
    - left click adds one unique snapped vertex
    - holding left does not create freehand vertices
    - first point locks the selected face
    - undo removes exactly the latest point and reopens a closed contour
    - close requires at least three unique vertices
    - self-intersection is rejected
    - review is locked until the polygon is closed and valid
    - new targets use the existing text-entry workflow for a validated,
      non-duplicate name
    - normalized face-local points are committed and persisted

The editor overlay does not alter Base Color. It renders a black outer
stroke, bright cyan inner stroke, and distinct start/intermediate/end
vertices.

MVP scope remains one named polygon, on one face, per authoring pass.

============================================================
10. COMMIT / SAVE / SAVE-AS BEHAVIOR
============================================================

COMMIT WORKING EDIT TO TARGET:
    - mutates only the canonical in-memory StaticParticleAsset
    - does not write to disk
    - clears dirty status after success

SAVE CURRENT SP_ASSET:
    - rejected while the working pass is dirty
    - writes the clean canonical target through the existing bundle
      persistence path

SAVE STATIC PARTICLE AS:
    - uses existing text entry
    - may include an uncommitted working edit
    - correctly includes a dirty working texture even when the selected
      display preview source is COMMITTED
    - asks for a Surface Target name first when a dirty NEW contour is
      unnamed
    - creates/reloads a new bundle, registers it in the shared
      repository, and makes it the current TextureMap target
    - leaves the original canonical target unchanged
    - cancellation clears pending save-as name state cleanly

RETURN TO PIXEL GRID:
    - preserves the exact working pass

RETURN TO AUTHORING CYCLE SETUP:
    - abandons an uncommitted pass and restores the canonical base
